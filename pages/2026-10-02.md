結論：正本を「機体」でなく GitHub に置き直し、galleria に森の完全な複製と grasp を持たせる

いちばん大事な点から書きます。いまのボトルネックは「入口がどこにあるか」より、正本を Mac という機体に置いていることです。これは実際に起きています。9/30 に galleria で public 12 wiki を横断監査し、本当の食い違いを14件見つけました。ところが修正は当てられず、next.d/2026-09-30-forest-findings-apply-on-mac.md に「正本は Mac の作業コピーなので、Mac のセッションを待つ」と書かれたまま止まっています。オフラインになりうる機体を正本にすると、常時オンラインの側がその機体を待つことになります。

実測した現状（2026-10-02）
- galleria WSL の grasp ストアは 8/21 から更新されていない（~/.grasp/grasp.sqlite、Mac から scp した複製）。
- Mac 側は push が遅れています。... が未 push です。さらに 47 wiki のうち約15個は remote がありません。galleria からは、これらが古いか、まったく見えないかのどちらかです。
- galleria の Windows 側 git には GitHub 認証があり、galleria-wiki を自分で push しています（今日だけで5 commits）。WSL 側には認証がありません（~/.ssh 無し、gh 無し）。
- WSL の home に node 20 が入りました。grasp sync を galleria で回せる可能性がありますが、未確認です。
- ついでに見つけたこと：Mac の ~/galleria-wiki（read 専用の複製のはず）が origin より2 commits 先行していて、pull すると分岐エラーになります。

設計案
- 正本は GitHub の origin、両機は clone。「Mac が正本」という言い方をやめます。そのうえで push を人間の規律に任せず自動化します。Mac は launchd、galleria は systemd timer を使い、それぞれ fast-forward できる範囲だけ push/pull し、ぶつかったら通知します。これで、Mac がオフラインの間も最後に push した時点までは galleria から見えます。
- galleria の WSL ext4 に ~/forest を作り、許可した corpus を clone して、grasp ストアは galleria 上で作り直します（scp の複製はやめます）。NTFS ではなく ext4 に置くのは、CRLF ノイズと長いファイル名の制約を避けるためです。wikis.yaml は Mac の絶対パスを書いているので、機体ごとのレジストリにします。
- 汎用の入口は galleria WSL の grasp-nishio session（claude remote-control）にします。Mac からもスマホからも同じ session に入れます。Mac で直接作業するのは、Dropbox の実体ファイルや動画素材のような Mac にしかない資源を扱うときだけにします。そもそも Mac がオフラインのときは Claude 自体が動かないので、入口を手放しても失うものはほとんどありません。
