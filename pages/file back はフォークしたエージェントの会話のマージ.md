from [[チャットのフォーク]]

2026-10-15
- LLM Wikiの[[file back]]がなぜ僕にとって重要だったか
    - 「[[フォーク]]」してブランチに分かれたエージェントの会話の「[[マージ]]」に相当する操作が必要だったから
    - mergeとかreconcileのイメージ
- マージ操作が存在しなかった時代、人間が各ブランチを見て把握し、統合してドキュメントに残す必要があった
- file backが生まれたことで、人間はひと段落ついたスレッドにfile backと呼びかけることでディスクに永続化させることができる
    - このときにエージェントは自分が書こうとしているページの周辺を読むので、概念的な意味で「conflict」が起こっているならそれを解消してくれる
    - ファイル的な意味でconflictが起こっているブランチにmergeの指示を出したらコンフリクトの解消をしてくれるのと似た構造
    - 概念レベルでのコンフリクト解消をやる
- なので複数ブランチを作っても解消するタイミングでの負担が少なくなり、そのことによって気軽にどんどんブランチを作るようになった
    - [[fork は分岐と破棄の判断を decouple した]]
    - 分岐のコストだけでなく、合流のコストも下がった
