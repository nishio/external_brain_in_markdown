---
title: "人間のAIに対する判断移譲"
---

2026-10-20
人間とAIの関係の議論で「最終判断は人間がやる」などといった議論があり、これは数年前の段階ではまあ妥当なものだったが、2024~2026年の2年間で起きたことを踏まえると解像度が低すぎると感じている。
この期間に「作業をAIに任せる」に加えて、「実行を許可する判断」「人間に質問するかどうかの判断」も委ねるようになった。

背景にある問題意識としては、AIと人間の速度差が開いていって、人間の承認待ちがボトルネックになったこと。
- 2025-09-02 Audrey Tangの [[⿻ Plurality & 6pack.care]] における「人間よりもAIが早くなる時代、人間が庭でAIが庭師」
    - > As AI becomes a thousand, perhaps ten thousand times faster than us, we face a fundamental asymmetry. We become the garden; AI becomes the gardener.
- 2026-10-04 [[リバースアラインメント：多元的社会はAIを受容できるか]]での[[岡 瑞起]]の「[[AI間のコミュニケーション速度は早くなったが人間は遅いまま]]」という指摘
    - エージェントが毎回人間を呼ぶと、人間の注意がボトルネックになる。
    - めったに呼ばないと、人間は探索の行方に関わる機会を失う。


2024年以前、ソースコードの実装においてGithub Copilotなどのツールは「AIが提案をする」「人間がそれを受理すると編集される」という仕組みだった。2024年はこの構図が変わった年だった
- 3/12：[[Devin.ai]]発表
    - シェル・エディタ・ブラウザを与え、計画から実装・テストまで進める「AIソフトウェアエンジニア」を提示
- 同時期、[[Cursor]]がAIを組み込んだコードエディタとして登場。
- この時期、Devinは今でいう「サンドボックス」に近い、AIエージェントが活動するための仮想マシンを用意するスタイルだった。一方で他の多くのAIエディタやエディタ拡張は、サンドボックスを作成することをユーザ側のタスクにしていた。面倒臭がってサンドボックスを作らずに生の環境を触らせるユーザが多く発生した。

2024年末、Devin.ai的な完全自走のメリットと、いちいち承認が必要なローカルの開発環境のめんどくささから、一部のユーザが人間の承認なしに実行させようとし始める。
- 2024/12/17	Cursor 0.44
    - Agent がターミナルコマンドを自動実行できるようになる「Yolo Mode」が導入された
        - 当時の筆者の肌感としては「サンドボックスを作らずに生環境でターミナルコマンドを自動実行できるようにするのは流石にやばいだろ、AIがうっかりミスで重要なファイルを消したり上書きしたりするかもしれないじゃん」という感じだった
        - Yoloってどういう意味なのか筆者は知らなかったんだけどChatGPTいわく:
            - > YOLO = You Only Live Once（人生は一度きり）の略です。「人生は一度きりだから、思い切ってやろう」という意味の俗語です。そこから、コーディングエージェントでは逐一の確認・承認を省いて実行するモードの名前に使われています。
- 2025/2/24　Claude Code v0.2.9
    - ツール実行の承認確認を省略する --dangerously-skip-permissions が存在。この時点ではネット接続のないDocker環境に限定されていた。
        - 筆者の肌感「まあ、ネット接続のないDocker環境ならいくら壊したとしてもその環境が壊れるだけだからいいか。Docker環境は適宜スナップショットを取っておいて壊れた時に戻せるようにしといたらいいよね」
    - 2025/3/18	Claude Code v0.2.47
        - Shift+Tabでファイル編集の自動承認を切り替える機能を記録。それまでは「どんな編集をするか」を人間が編集前にレビューして承認していたが、それをやめてAIに自由にファイルを編集させる方向へ。
            - 筆者の肌感「まあプロジェクトフォルダ内に限定するなら、当然Git管理しているので万が一大事なファイルを上書きしてもロールバックできるし実害ないのでは？」「ロールバックの単位を小さくするために細粒度で自動的にCommitさせよう」
- 2025/4/16	Codex CLI公開
    - 初期READMEに Suggest／Auto Edit／Full Autoの3つのモードがある。読むだけ、編集までOK、コマンド実行までOK、の3種類。Full Autoはサンドボックス内で動作する設計だった。Claude Code v0.2.9と同じだね
    - この推奨3モードとは別に「--dangerously-auto-approve-everything」もあった
        - 同日、これを--yoloにする提案が出されていた
        - 2025/6/25	Rust版Codexに--dangerously-bypass-approvals-and-sandboxが追加される。承認確認の省略と、サンドボックスの解除を同時に行う
            - 感想「なんて野蛮な」
        - 2025/8/7 上記フラグの別名として--yoloを追加

2025/10/16	Claude Code v2.0.21　選択式の質問専用ツール、のちのAskUserQuestion
- これ以前は、AIが何かをしようとして、人間が「承認する」「拒否する」の2択だったのだが、たとえば実装方法を2案出して「どっちがいい？それとも自由記述する？」という問いかけをAIが実行できるようになった

2026年の2~8月の間に、AIが意思決定をする方向に大きく方針転換が起きた
- 2026/2/17	逆瀬川氏が「人間に質問する前に読み込ませ、自ら判断・検証させる」スキル設計を公開。「聞くかどうか」の判断を委譲する具体例。[Agentワークフローで人間がボトルネックにならないためのSkill設計 - 逆瀬川ちゃんのブログ](https://nyosegawa.com/posts/claude-code-verify-command/?utm_source=chatgpt.com)
    - この時期のAI Agentワークフローを活用している人の温度感がよくわかる記事
- 2026/3/24	Claude Code auto modeをTeam向け研究プレビューとして公開。
    - 実行前に分類器が危険性を判定し、許可できる操作を自動で通す。承認する役割をAIが担う。
- 2026/4/23	Codexアプリの変更履歴にAutomatic approval reviewsが登場。4/30に技術説明を公開。
    - サンドボックス境界を越える要求を、作業担当とは別のエージェントが審査する。
- 2026/5/28	Claude Code Dynamic Workflow
    - Claude自身が複数のエージェントを動かすJavaScriptのスクリプトを作り、実行する仕組み
    - 公式発表でもAuto modeとの併用を推奨している: [Introducing dynamic workflows | Claude by Anthropic](https://claude.com/ja/resources/articles/introducing-dynamic-workflows-in-claude-code)
- 2026/7/10	Claude Code auto modeを全ユーザー向けに一般提供
- 2026/8/14	Claude CodeのPro・Max・Teamで、新規セッションの既定をauto modeへ変更。8/7発表。AIによる承認判断が、利用者が選んで有効にする機能から標準設定へ移った。

2026-10-20現在、「最終判断は人間がやる」という主張が解像度低いものに感じるのは、「何が人間の判断すべきものか」が明瞭になってない発言だからだと思う。
- 現実には人々は2025年には「ファイルを書き換える」という判断を手放し、2025年末には「ターミナルコマンドを実行する」という判断も手放した。手放す方が利便性が高かったからである。
- そして2026年8月、「何が人間の承認を必要とするものか」という判断自体をAIに任せるようになっている。
